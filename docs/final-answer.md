# Final answer

I would separate prediction from permission. A predictive engine may estimate an aggressive batch from observed answer rate, ringing calls, setup time, and expected agent releases, but it cannot call the provider. A mandatory Safety Controller recalculates capacity using a conservative confidence bound, enforces an operator-owned risk ceiling, and persists an explainable approval, reduction, rejection, or progressive fallback. PostgreSQL then atomically owns every borrower/agent reservation, while provider idempotency and an append-only event inbox make retries safe. When information is cold, stale, degraded, or changing rapidly, the system deliberately gives up predictive utilization and behaves progressively. This captures most predictive benefit when evidence is strong while retaining a deterministic, non-bypassable safety boundary.
